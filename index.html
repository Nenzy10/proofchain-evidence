100% client-side. Your files never leave this device — hashing happens in your browser.

What this proves — and what it does not

ProofChain Evidence fingerprints a file with SHA-256 at the moment of intake and issues a canonical evidence receipt: file name, size, hash, timestamp, and case/matter ID, with a hash-chained chain-of-custody log. Later, anyone holding the receipt can re-hash the file and get a clear MATCH / MISMATCH verdict — proof the file's contents have not changed since the moment it was hashed.

Honest limits: a hash proves content integrity from the moment of hashing. It does not prove who created a file, when it was originally created, or that its contents are true. This tool is an integrity-verification aid — it is not a court certification and makes no claim of legal admissibility.

    How it works
    
    
      
      
    1. Intake. The file is read locally and hashed with SHA-256 (Web Crypto API). The original file is never uploaded or stored.
      2. 
      
    2. Receipt. A canonical JSON receipt binds the hash to the file name, byte size, case/matter ID, and UTC timestamp. A digest of that core anchors the receipt.
      3. 
      
    3. Custody. Each custody event is hash-chained to the previous event and to the core digest. Altering any earlier entry breaks every later link — tampering is detectable.
      4. 
      
    4. Verification. Re-hash the file and compare against the receipt. One changed bit produces a different hash and a MISMATCH verdict.
